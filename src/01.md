# Organization

## The Big Three

- Decompose a computer.
- At least three basic units:
    - *I/O* (Input/Output)
    - *Memory*
    - *CPU* (Central Processing Unit)


## I/0

- Where data arrives from the outside world
- Where data is sent to the outside world
- Where data is archived for the "long term"
    - Persists through power cycles
- Keyboard, mouse, monitor, HDD
- Symbols to bits (and back)

## Memory

- Where data is stored when in usage
    - Arrays, trees, matrices (not files, really)
    - Often called RAM
    - "Handful" of GBs
- Key-value storage over *addresses* and *values* or contents

## CPU

- Data is manipulated
    - Arithmetic operations
    - Control flow
    - Load and store operations
        - How values in memory are alterated
        - How I/O values are manipulated.
- This is the cool one.

## "Processing"

- A CPU performs low-level operations called *instructions*
    - These are cool, and good.
- Four types
    - Arithmetic
    - Logical
    - Comparison (or tests)
    - Control

## Examples

- Arithmetic
    - $+$, $-$, $\times$, $\div%
- Logical
    - `NOT`, `AND`, `OR`, `XOR`
- Comparison
    - $\gt$, $lt$, $=$, $\geq$, $\leq$
- Control
    - Go to a place in code, return to call site. 

## Aside: Goto

- Back in the good (bad) old days, we didn't have `for` and `while`.
- We had to make them overselves, out of `goto`.
    - Place a label in between two lines of code.
    - Invoke via `goto` keyword + label.
    - Syntax (punctuation) matters here, of course.

    - `goto`

## Solution

<details>
```{.c filename="fact.c"}
int fact(int n) {
	int r = n;
iterate:
	if (--n) {
		r *= n;
		goto iterate;
	} else {
		return r;
	}
}
```

Bonus if your code compiles to identical `.s` as a `while` solution.

</details>

## The Ouroboros

- Instructions are also stored in memory.
    - Alongside data.  Just bits.
- CPU "fetches", "decodes", and then executes.
- Then the location of the next instruction is determined.
    - Usually next address.
    - Unless you hit a `goto`

## Some Terms

- "Fetch" and "Decode"
    - Technical terms in CPU design.
- The instructions-as-data are termed "machine language"
- "Mnemonics" are socially constructed manners of referring to machine code.
    - These mnemonics form assembly language (asm)
    - `movl	%eax, %edi`

## Von Neumann, Formally

- A central arithmetic unit to perform arithmetic operations;
- A central control unit to sequence operations performed by the machine;
- Memory that stores data and instructions;
- An "outside recording medium" to store input to and output from the machine;
- Input and output mechanisms to transfer data between the memory and the outside recording medium.

## Competing Formulation

> The competing formulation known as the *Harvard architecture* differed in that information describing actions (say, *executables* or "stored memory programs" or "instructions") and information for read-write (say *data files* or just "data") had distinct storage mediums.

- As far as I know, none of these were ever made.
- Theoretical idea.

# RISC-V

## RISC-V

> [RISC-V (pronounced "risk-five")  is a free and open standard instruction set architecture (ISA) based on reduced instruction set computer (RISC) principles. Unlike proprietary ISAs such as x86 and ARM, RISC-V is described as "free and open" because its specifications are released under permissive open-source licenses and can be implemented without paying royalties.](https://en.wikipedia.org/wiki/RISC-V)

## Rationale

> [RISC-V was begun with a goal to make a practical ISA that was open-sourced, usable academically, and deployable in any hardware or software design without royalties... The RISC-V authors are academics who have substantial experience in computer design, and the RISC-V ISA is a direct development from a series of academic computer-design projects, especially Berkeley RISC. RISC-V was originated in part to aid all such projects.](https://en.wikipedia.org/wiki/RISC-V#Rationale)

# Instructions

## Operand Types

- Consider `addi`
    - Stands for "add immediate"
    
| Opcode | Destination | Operand<sub>1</sub> | Operand<sub>2</sub> |
| :---   | :---        | :---                | :---                |
| `addi` | `sp`        | `sp`                | `48`                |

- Three operand types:
    - Destination (`sp`)
    - Source (`sp`)
    - Immediate (`48`) - a numeric literal
    
## Operand Types

- Source and Destination are mutually exclusive.
    - An operand cannot be both.
    - However, the same register can be both.
        - Is specified twice: `addi  sp,sp,48`
- Operand<sub>1</sub> and Operand<sub>2</sub> may either be a register or an "immediate"
    - A literally numeric value, like `7` or `3`.
    
## Meaning of an Instruction 
 
- Operations are abbreviated into opcodes
- Instructions are specified with a regular syntax.
    - Opcodes precede arguements.
    - Destinations precede sources.
    - Immediates are terminal.
    
## Why this order?

- Consider the highest possible level language:

```{.py}
x = y + 1
```

- Consider the following assembly:

```{.s}
addi rx, ry, $1
```

- That's why.

## Instructions are Simple 
 
- Computers interpret “programs” by translating them from some (1) scripting or (2) programming language
- The output is a sequence of "low level" simple instructions.
- This output is, in point of fact, a bit array.

## Compiled Languages

- Compiled languages like C and Rust are:
    - Expressed in text
    - Submitted to an executable (compiler)
    - The executable outputs some other executable (the program).
    
## Interpreted Languages

- Interpreted languages like Python and JavaScript are:
    - Expressed in text
    - Submitted to an executable (interpreter)
    - This interpreter maps the text to machine instructions which are then run.
- Usually more complicated than this in practice.
    
 
## Instructions are Binary 
 
- Computers interpret “assembly programs” by translating them from their
 mnemonic simple instructions into strings of bits.
- Let's examine...

```{.c filename="min.c"}
int main() {
        return 0;
}
```

## Compile... ish

## A Series of Instructions

- Executables are mostly sequences of instructions.
    - Remember, we have access to `goto`
- Instructions are retrieved sequentially from memory
- An instruction executes to completion before the next instruction is started
- There are a lot of corner cases.

## Example

- Say we had the following.

```{.s}
li  a0,0
li  a1,6
add a0,a1,a1
add a0,a0,a0
add a0,a0,a0
sub a1,a0,a1
```

## Load Immediate

- `li` stands for "load immediate"
- It is used to place a (1) value into a (2) register
    - Values are immediates
    - Register is the destination.
- We can imagine this ourselves by making a table of register values.
    - Perhaps a... registry (hence the name).

## Key Idea

> Memory holds not only data, but coded instructions that make up a program.

- CPU "fetches" and "executes" instructions from memory
- Programs **are** data, just interpreted differently.
- Main memory is a single resource pool.

# RISC-V Memory


## Details
 
- Memory locations are addressable in different sized chunks 
    - 08 bit chunks (bytes) 
    - 16 bit chunks (shorts)
    - 32 bit chunks (words)
    - 64 bit chunks (longs)

## In Use

- Bytes have their own address.
    - We say "RISC-V is a byte-addressable machine"
- Most instructions are one word.
    - So, a byte-ish per opcode/operand.
- If you need to work with individual bits, use relevant instructions.
    - Bitwise operations.
