# Organization

## The Big Three

- Decompose a computer.
- At least three basic units:
    - *I/O* (Input/Output)
    - *Memory*
    - *CPU* (Central Processing Unit)


## I/0

- Where data arrives from the outside world
- Where data is sent to the outside world
- Where data is archived for the "long term"
    - Persists through power cycles
- Keyboard, mouse, monitor, HDD
- Symbols to bits (and back)

## Memory

- Where data is stored when in usage
    - Arrays, trees, matrices (not files, really)
    - Often called RAM
    - "Handful" of GBs
- Key-value storage over *addresses* and *values* or contents

## CPU

- Data is manipulated
    - Arithmetic operations
    - Control flow
    - Load and store operations
        - How values in memory are alterated
        - How I/O values are manipulated.
- This is the cool one.

## "Processing"

- A CPU performs low-level operations called *instructions*
    - These are cool, and good.
- Four types
    - Arithmetic
    - Logical
    - Comparison (or tests)
    - Control

## Examples

- Arithmetic
    - $+$, $-$, $\times$, $\div%
- Logical
    - `NOT`, `AND`, `OR`, `XOR`
- Comparison
    - $\gt$, $lt$, $=$, $\geq$, $\leq$
- Control
    - Go to a place in code, return to call site. 

## Aside: Goto

- Back in the good (bad) old days, we didn't have `for` and `while`.
- We had to make them overselves, out of `goto`.
    - Place a label in between two lines of code.
    - Invoke via `goto` keyword + label.
    - Syntax (punctuation) matters here, of course.


## Example

- By the way, these compile to identical assembly.

## Exercise

- Write factorial in C.
- Use:
    - `goto`
- Don't use:
    - `for`
    - `while`
    - Recursion
    - An LLM

## Solution

<details>
```{.c filename="fact.c"}
int fact(int n) {
	int r = n;
iterate:
	if (--n) {
		r *= n;
		goto iterate;
	} else {
		return r;
	}
}
```

Bonus if your code compiles to identical `.s` as a `while` solution.

</details>

## Helpful Sample Code

- I use this often.

```{.c filename="template.c"}
#include <stdio.h>
#include <stdint.h>

int help(int n) {
iterate:
	if (0) {
		goto iterate;
	} else {
		return 0;
	}
}

int main() {
	int n;
	while (1) {
		scanf("%d", &n);
		printf("%d\n", help(n));
	}
	return 0;
}
```

## Memory

- Memory is organized as collections (really arrays) of bits.
- These arrays of bits of respresent... everything.
    - Integers (signed or unsigned), floating point values, strings
    - Pixels, so both image and video.
- Within computers, a **single** and **enormous** array for which indices are terms *addresses*.

## The Ouroboros

- Instructions are also stored in memory.
    - Alongside data.  Just bits.
- CPU "fetches", "decodes", and then executes.
- Then the location of the next instruction is determined.
    - Usually next address.
    - Unless you hit a `goto`

## Some Terms

- "Fetch" and "Decode"
    - Technical terms in CPU design.
- The instructions-as-data are termed "machine language"
- "Mnemonics" are socially constructed manners of referring to machine code.
    - These mnemonics form assembly language (asm)
    - `movl	%eax, %edi`

## Von Neumann, Formally

- A central arithmetic unit to perform arithmetic operations;
- A central control unit to sequence operations performed by the machine;
- Memory that stores data and instructions;
- An "outside recording medium" to store input to and output from the machine;
- Input and output mechanisms to transfer data between the memory and the outside recording medium.

## Competing Formulation

> The competing formulation known as the *Harvard architecture* differed in that information describing actions (say, *executables* or "stored memory programs" or "instructions") and information for read-write (say *data files* or just "data") had distinct storage mediums.

- As far as I know, none of these were ever made.
- Theoretical idea.

## Historical use case

- Historical computing devices had no onboard storage and programs lived on e.g. external tapes.
    - The Harvard architecture is a helpful model in this case.
