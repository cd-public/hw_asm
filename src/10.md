## System Design

- Contract: an agreement to adhere to specified behavior.
    - "I will use 1 to represent black" vs. "...white"
- System: a structure **guarantee** to exhibit specied behavior *given certain assumptions*
    - Usually that underlying systems adhere to contracts.
    - Monitor will display colors accurate under adequate power.

## We Claim

> Every system component will have clear obligations and
responsibilities. If these are maintained we have every
right to expect the system to behave as planned. If
contracts are violated all bets are off.

## A Contract

- We previously used a contract this term:

```{.c}
int sqrt(int x) {
    int r = 0;
    while (++r * r <= x) {}
    return r - 1;
}
```

- Our square root assumed a positive `int`
    - A proper contract would use e.g. `unsigned`.

## Digital Contracts

- Digital implementation keeps the contracts *simple* (or *more simple*).
- The price we pay?
    - All the information that we transfer between components is only one bit!
    - But, in exchange, we get reliable, modular, and reproducible systems.

## Digital Processing 

- Term: "Combinational device"
- A digital element that has
    - one or more digital inputs (a bit array of nonzero length)
    - one or more digital outputs ("")
    - a functional *specification* that details the value of each output for every
possible combination of valid input values

## Another component

- Kaki Ryan (and I) have a bit of background in *real-time computing* so we further specify:
    - A timing specification consisting (at a minimum) an upper bound on the required time for the device to compute

## Example

- Logical not over bytes.
- Express a bit as a value in $\{0, 1\}$
- Express 8 bits as an 8th dimensional value, so $\{0, 1\}_8$
$$
f(x) = \begin{cases}
    0  & \text{if } 1 \notin x  \\
    1  & \text{if } 1 \in x \\
\end{cases}
$$

- I'd typically claim this should be a constant factor of bit length in time cost.
    - Fun question: How about division?

## Other Examples

- We wrote things very close to specifications for `CHOICE` and `MAJORITY`/`MEDIAN` for [SHA](https://cd-public.github.io/sysinc/20_sha256.html#ternary-bitwise).

$$
\text{CHOICE}(U, V, W) = (U \land V) \oplus (\lnot U \land W)
$$
$$
\text{MEDIAN}(U, V, W) = (U \land V) \oplus (U \land W) \oplus (V \land W)
$$

## Combination Digital Systems

A system of interconnected elements is combinational if:

- Each circuit element is combinational
- Every input is connected to exactly one output or directly to some source of 0’s or 1’s
- The circuit contains no directed cycles
- But, in order to realize digital processing, elements have one more requirement!


## Noise Margins

- Key idea: Don’t allow “0” to be mistaken for a “1” or vice versa
- To implement devices with high reliability, we outlaw “close calls” via a representation convention which forbids a range of voltages between “0” and “1”.
- Ensure the valid input range is more tolerant (larger) than the valid output range

## Startup Costs

- Our definition of valid does not preclude inputs and outputs from passing through invalid
values.
    - In fact, they must, but only during transitions. 
    - Our specifications allow for this (i.e. outputs are specified some time $T$ after inputs become valid).

# Transistors

## Physical Building Blocks

- Transistors are the physical building blocks of modern computers!
A transistor is the physical device we use to turn continuous electrical behavior into digital 0s and 1s.
- You can think of it as an electrically controlled switch that turns current on or off.
- "Programmable logic"




## Switch-like

- Switches are controlled by *physical contact*
- Transistors are controlled by a *voltage*

## Binary States

- Transistors can be in two distinct states: on or off
- This is why our machines communicate in binary (1s and 0s)!

## Logic Levels

- Instead of specifying the exact voltage level (e.g. 3V or 5V), we’ll simply use binary terms when discussing transistors.
    - This is an *abstraction*.
- We’ll either have a high voltage or a low voltage.

## High & Low

- There are a few different terms for these voltage levels.
    - High voltage: logic high = logic 1 = 1
    - Low voltage: logic low = logic 0 = 0
- I just call these "high" and "low"

## Transistors

- We will be working with two types of transistors
    - nMOS transistors (today)
    - pMOS transistors (someday)

## Terminals

- There are three terminals
    - <span style="color:blue">Gate</span>: controls whether the transistor is on or off
    - <span style="color:red">Source</span> and <span style="color:red">Drain</span>: endpoints
