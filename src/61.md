## Definition of Performance

For some program running on machine X,
| Performance |     | = Program Executions / Time |     |     | (executions/sec) |
| ----------- | --- | --------------------------- | --- | --- | ---------------- |
|             |     | X                           |     |     | X                |
"X is N times faster than Y"
|     | Performance |     | / Performance | = N |     |
| --- | ----------- | --- | ------------- | --- | --- |
|     |             |     | X             | Y   |     |
Problem:
Machine A runs a program in 20 seconds
Machine B runs the same program in 25 seconds
| Performance |     | = 1/20 |     | Performance | = 1/25 |
| ----------- | --- | ------ | --- | ----------- | ------ |
|             |     | A      |     |             | B      |
Machine A is  (1/20)/(1/25) = 1.25 times faster than Machine B

## Program Clock Cycles

Instead of reporting execution time in seconds, we can also use cycle counts
(sec/program) * (clocks/sec) = clocks/program
Clocks are when machine-state changes (synchronous abstraction):
time
cycle time = time between rising edges of the clock = seconds per clock
clock rate (frequency) = clocks per second (1 Hz. = 1 clock/sec)
A 200 Mhz. clock has a 1 / ( 2 0 0 * 1 0 6 ) = 5 .0 x 10-9 = 5 nS cycle time
Overclocking: improves performance
(seconds/program) by decreasing the
cycle time (seconds/cycle), while hoping
that the functional blocks continue to
operate as specified.

## Clock Period = 500ps

■ Our circuit does not operate correctly with a period
of 500ps
■ Why?
– The adder cannot finish its operation before the
next rising edge of the clock
– The output register ends up reading garbage

## Take Away: How to determine the minimum clock period?

min clock period = clk-to-q delay of the input registers + adder propagation delay

## In General…

min clock period = clk-to-q delay of the input registers + longest combinational path

## Min Clock Period

■ Why do we not include the clk-to-q delay of the output register when determining the min
clock period?
In one clock cycle, we need to read the input registers, compute their sum, and ensure the value is ready for
the output register before the next rising edge of the clock. The value will not pass through the output register
until the next rising edge of the clock.
