Delay slot: an instruction slot that comes

after a branch or a jump and the processor is guaranteed to execute that instruction Branch Fixes before the branch takes effect Problem: Two instructions following a branch are fetched before the branch decision is made (to take or not to take) Solutions: 1. Program around it. Define the ISA such that the branch does not take effect until after instructions in the “DELAY SLOTS” complete. This is how MIPS pipelines work. It leads to odd looking code in tight (short) loops. You could always put “NOPs” in the delay slots. 2. Detect the branch decision as early as possible, and ANNUL instructions in the delay slots. This is what RISC-V does.

Early Detect and Annul

Detect branch and jump instructions and It helps if … the ALU is make the branch decision in the decode stage. not used by loop: add t0,t0,t0 branch addi t1,t1,-1 We then annul the following instruction by instructions bne t1,x0,loop forcing it to be a NOP (addi x0, x0, 0) srai t0,t0,8 sub t1,t0,t1 Time (in clock cycles) i i+1 i+2 i+3 i+4 i+5 P i Fetch add t0,t0,t0 addi t1,t1,-1 bne t1,x0,loop srai t0,t0,8 add t0,t0,t0 addi t1,t1,-1 p e l i Decode add t0,t0,t0 addi t1,t1,-1 bne t1,x0,loop srai t0,t0,8 nop add t0,t0,t0 n e nop Execute add t0,t0,t0 addi t1,t1,-1 bne t1,x0,loop srai t0,t0,8 We detect the branch in the decode stage then the instruction in the fetch stage can be ANNULLED and the next PC changed.

Impact on the Hardware

Two changes: Add H/W to test if the branch is taken during 1. annul register access. Easy for beq and bne (just NOR together the bitwise XORs). Use this zero detection from the decode stage, z , to D select the next pc (btype = 0, pcsel =1) Add a multiplexer to replace the already 2. fetched instruction with a NOP, and, thus ANNUL it.

The cost of taken branches

When an RISC-V branch is taken the branch instructions are effectively 2 cycles rather than 1 when they aren’t. In a MIPS-like instruction set, one can often fill the delay slots with useful instructions, but they are executed whether or not the branch is taken. The RISC-V approach is easier to understand, and since it does not “EXPOSE” the pipeline, it also allows for an alternative number of pipeline stages to be implemented in future designs, while conserving code compatibility. Lastly, using RISC-V, many conditional branches can be eliminated using the condition execution, which pipelines beautifully!

before the branch takes effect

## The cost of taken branches

When an RISC-V branch is taken the branch instructions are effectively 2 cycles rather than
1 when they aren’t. In a MIPS-like instruction set, one can often fill the delay slots with
useful instructions, but they are executed whether or not the branch is taken.
The RISC-V approach is easier to understand, and since it does not “EXPOSE” the pipeline, it
also allows for an alternative number of pipeline stages to be implemented in future
designs, while conserving code compatibility.
Lastly, using RISC-V, many conditional branches can be eliminated using the condition
execution, which pipelines beautifully!
