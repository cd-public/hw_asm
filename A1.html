SOURCE BYPASSING

Simplified datapath to focus on forwarding for r-format

Forwarding rs1

sub x7, x5, x2 add x5, x3, x4

Forwarding rs1

There is a data hazard between these two instructions! We can resolve this hazard by inserting two stalls. Or we can use a technique called forwarding! sub x7, x5, x2 add x5, x3, x4

The value that is to be written to x5 is available at the ALU output

sub x7, x5, x2 add x5, x3, x4

Instead of waiting for this value to be written back to the register

file, we can send it back to the sub instruction! sub x7, x5, x2 add x5, x3, x4

Instead of waiting for this value to be written back to the register

file, we can send it back to the sub instruction! We will send this value to the sub instruction when it moves into the execute stage. sub x7, x5, x2 add x5, x3, x4

Forwarding rs1

The value to be written to x5 is here sub x7,x5, x2 add x5, x3, x4

Forwarding rs1 We are forwarding the value to be written

to x5 to the dependent instruction. M u x sub x7, x5, x2 add x5, x3, x4

Forwarding rs1

M u x What if there was one instruction in between the dependent instructions? sub x7, x5, x2 or x8, x9, x10 add x5, x3, x4

Forwarding rs1 The value to be written to x5 is at the

output of the writeback mux. M u x sub x7, x5, x2 or x8, x9, x10 add x5, x3, x4

Forwarding rs1 The value to be written to x5 is at the

output of the writeback mux. M u x sub x7, x5, x2 or x8, x9, x10 add x5, x3, x4

Performance Analysis + Pipelining

Assume a 1 GHz clock. One clock cycle is 1 ns Assume a pipelined implementation where: ● Taken branches take 2 cycles. ○ Loads and stores take 2 cycles. ○ Assuming approximately 10% of instructions executed are ● branches, and of those 80% of the time they are taken, and 15% of instructions executed are loads or stores, what sort of real speed-up do we expect?

Some takeaways…

Design strategy: Focus our attention on placing pipelining ● registers around the slowest circuit elements (bottlenecks!) You can pipeline an RISC-V CPU even more. There exist ● implementations with 7, 8, and 9 pipeline stages. But the overhead of bypass paths and the number of stall cases increase . Memory access time is our real bottleneck! ●

previous result that is still in the pipeline
Problem: When a register source is needed from a later stage of the pipeline before
it is written.
Solutions:
1. Program around it. One could document the weird semantics-- “You can’t

instruction.” Would make make assembly language even harder to understand.
Would expose the pipeline, once again making future improvements difficult to
implement while maintaining code compatibility.

## Some takeaways…

Design strategy: Focus our attention on placing pipelining
●
registers around the slowest circuit elements (bottlenecks!)
You can pipeline an RISC-V CPU even more. There exist
●
implementations with 7, 8, and 9 pipeline stages. But the
overhead of bypass paths and the number of stall cases increase
.
Memory access time is our real bottleneck!
