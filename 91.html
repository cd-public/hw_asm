Code interacts with the

stack in 3 main ways: •At the beginning of the function, it will “push a stack frame onto the call stack” by moving SP downward to make space for its own stack frame. •During the execution of the function, it will use (positive) offsets from sp or fp to locate each of its local variables. •At the end of the function, before it returns, it will “pop the stack frame off the call stack” by moving sp back up to wherever it used to be, “destroying” its stack frame.

RISC-V BUG FIXING!

Bugs! .beq a0, x0, recur If n == 0, we should go to the base case, not the recursive case. So it should branch to the base case. Correct idea: beq a0, x0, base or restructure the code so recursion is skipped. Line 11 error j factorial This performs a jump but does not save the return address. Recursive calls require saving the return address so the function can return. Correct instruction: jal ra, factorial

Stack Management Policies
ALLOCATE k: reserve k WORDS of stack
addi sp,sp,-4*k
SP = SP - 4*k
DEALLOCATE k: release k WORDS of stack
addi sp,sp,4*k
SP = SP + 4*k
PUSH x: push Reg[x] onto stack
addi sp,sp,-4
Mem[SP - 4] = Rx
sw rx,(sp)
SP = SP - 4
lw rx,(sp)
POP x: pop the top of the stack into Reg[x]
addi sp,sp,4
Rx = Mem[SP]
SP = SP + 4

## Code interacts with the

stack in 3 main ways:
•At the beginning of the function, it will
“push a stack frame onto the call stack” by
moving SP downward to make space for its
own stack frame.
•During the execution of the function, it will
use (positive) offsets from sp or fp to locate
each of its local variables.
•At the end of the function, before it returns,
it will “pop the stack frame off the call stack”
by moving sp back up to wherever it used to
be, “destroying” its stack frame.
